# 역할 맡기 — `$ARGUMENTS`

한 프로젝트를 Claude 세션 여럿이 역할을 나눠 맡는다. 작업 폴더·git·Unity 에디터는 **하나를 같이 쓴다** — 그래서 아래 "담당"과 "에디터 잠금"이 규칙의 전부다.

## 맡는 절차

1. 인자가 `총괄 · 밸런스 · 개발 · UI · 기획` 중 하나가 아니면 사용자에게 묻는다.
2. 이 폴더의 `<역할>.md`를 읽는다(예: `.claude/skills/role/밸런스.md`).
3. `ListAgents`로 **내 세션 이름**과 살아 있는 세션을 본다.
4. `.claude/team/ROSTER.md`를 연다(없으면 아래 「명단 형식」으로 만든다).
   - ListAgents에 없는 세션의 줄은 지운다(죽은 세션).
   - 내 역할 줄에 **살아 있는 다른 세션**이 있으면 덮어쓰지 말고 사용자에게 묻는다.
   - 내 줄을 `역할 = 세션이름 (맡은 시각)`으로 쓴다.
5. 알린다 — 총괄이 아니면 총괄에게 `[등록] 밸런스 = <내 이름>`. 총괄이면 명단의 모든 세션에 `[등록] 총괄 = <내 이름>`.
6. 사용자에게 한 줄로: 맡은 역할 · 담당 범위 · 지금 명단.

**맥락이 요약돼 역할이 흐려졌으면**: ROSTER에서 내 이름을 찾아 `<역할>.md`와 이 파일을 다시 읽는다.

## 담당 — 고치는 곳 (원본은 이 표 하나)

| 역할 | 고치는 곳 |
|---|---|
| 총괄 | `HANDOFF.md` · `ROADMAP.md` · `CLAUDE.md` · `ARCHITECTURE.md` · `SCENE_MAP.md` · `SESSION_ZERO.md` · `README.md` · 명단 · git 커밋(사용자가 시킬 때만) |
| 밸런스 | `Assets/Data/**`의 **이미 있는 에셋의 수치**(체력·공격·비용·쿨다운·적 보드 구성 등) |
| 개발 | `Assets/Scripts/**`(UI 폴더 제외) · `Assets/Editor/**` · `Assets/Prefabs/**` · `Assets/Fx/**` · `ProjectSettings/**` · **새 SO 에셋 만들기** · 에셋의 설명 글 · 유닛·투사체 그림 배선 · 씬에서 Canvas 밖 오브젝트 |
| UI | `Assets/Scripts/UI/**` · UI 그림 배선 · 씬에서 Canvas 아래 오브젝트 |
| 기획 | `Docs/`의 기획서(`WorldWarGnorp_기물기획.md` 등) — 사용자·총괄이 시킨 반영만(사용자 10/9) |
| (총괄) | `Docs/TodoList/` · `Docs/Record/` — 절차는 `.claude/skills/testResultReview/SKILL.md`. `Docs/testResult/`는 사용자만 쓴다 |
| 사용자 | `GDD.md` — 시키지 않으면 아무도 안 고친다 · `Docs/`의 결정 자체 |

- **남의 담당 파일은 고치지 않는다.** 필요하면 담당에게 `[요청]`을 보낸다. 담당 세션이 명단에 없으면 총괄에게 묻는다.
- 새 기물을 만들 때 첫 수치는 개발이 기획서 값으로 넣는다. 그다음 조정은 밸런스가 한다.
- 문서에 반영할 일이 생기면 직접 쓰지 말고 `[보고]`에 "문서 반영: …"으로 적어 총괄에게 넘긴다.
- **git 쓰기(`add`·`commit`·`stash`·`checkout`·`restore`·`reset`)는 총괄만 한다.** 다른 세션이 작업 중인 파일이 함께 날아간다.

## 메시지

첫 줄 = `[종류] 보낸역할→받는역할: 한 줄 요약`. 종류는 `요청 · 접수 · 보고 · 질문 · 에디터 · 등록`.

- **요청**: 무엇 · 왜(사용자가 한 말 그대로) · 완료 조건 · 손댈 파일. 받는 쪽은 내 맥락을 모른다 — 문장만으로 완결되게 쓴다.
- **요청을 받으면 바로 착수한다**(사용자 결정). 먼저 `[접수]` 한 줄을 보내고, 하던 일이 있으면 그걸 끝낸 뒤 시작한다.
  CLAUDE.md §1의 갈림길을 만나면 **사용자에게 묻고**, 총괄에게 `[질문]`으로 "사용자 답 대기 중"이라고 알린다.
- 사용자가 그 세션에 직접 시킨 일이 총괄의 요청보다 먼저다.
- **보고**: 한 일 · 검증(무엇을 어떻게 쟀나, 사용자 문장과 대조) · 못 본 것 · 바꾼 파일 목록 · 문서 반영할 것.
- 답장은 받은 메시지의 `from`으로 보낸다. 상대가 응답하는지 확인하려고 `ListAgents`를 반복해서 부르지 않는다. 기다릴 땐 `notify_when_idle`을 쓴다.

## 에디터 잠금 (CLAUDE.md §6의 "알리고 쓴다"를 이렇게 한다)

ROSTER의 `에디터:` 줄 하나가 잠금이다. **에디터를 바꾸는 MCP 호출 전부**(오브젝트·컴포넌트 수정, 플레이모드, refresh·컴파일, 씬·에셋 저장)에 잠금이 필요하다. 읽기(조회·콘솔·캡처 아닌 상태 조회)는 잠금 없이 해도 된다.

1. 줄이 `비어 있음`이면 `에디터: <역할> (<시각>~)`로 쓰고, **다시 읽어 내 역할이 적혀 있는지 확인한 뒤** 시작한다(동시에 쓰면 덮인다 — 남의 이름이면 2번으로).
2. 차 있으면 줄 끝에 `· 대기: <역할>`을 붙이고, 잡은 세션에 `[에디터] 대기` 메시지를 `notify_when_idle: true`로 보낸 뒤 다른 일을 한다.
3. 다 쓰면 플레이모드를 끄고, 일시정지를 풀고, 콘솔 컴파일 에러가 0인지 확인한다. 그다음 줄을 `비어 있음`으로 되돌리고, 대기열 첫 세션에 `[에디터] 반납`을 보낸다.
4. 잡은 세션이 ListAgents에 없으면 잠금은 풀린 것이다. 잡은 지 **30분이 지났으면** 그 세션에 묻는다. 답이 없으면 총괄이 정한다.
