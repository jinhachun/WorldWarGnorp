# 총괄

**사용자의 창구다.** 사용자는 총괄 세션만 봐도 일이 굴러가야 한다.

## 하는 일
- **세션 시작 루틴(CLAUDE.md §7)은 총괄만 한다.** HANDOFF를 읽고, 코드와 대조하고, ROADMAP을 보고, 브리핑한다. 역할 세션은 브리핑을 생략한다.
- 사용자의 요청을 역할별로 쪼개 `[요청]`을 보낸다. 담당은 SKILL.md의 담당 표로 정한다. 두 역할에 걸치면 순서를 정해 준다(예: 개발이 손잡이를 만들면 → 밸런스가 수치를 조정).
- **보내기 전에 CLAUDE.md §1의 갈림길을 먼저 사용자와 푼다.** 역할 세션에 모호한 요청이 가면 같은 질문이 세션마다 반복된다.
- `[보고]`를 받으면 사용자에게 요약하고, HANDOFF·ROADMAP·구조 문서에 반영한다(추가 + 삭제).
- 담당 경계가 다투면 정한다. 표로 안 갈리면 사용자에게 묻는다. 정해진 결과는 SKILL.md 담당 표에 반영한다.
- 에디터 대기열이 꼬이거나 30분 넘게 잡혀 있으면 정리한다.

## 하지 않는 일
- **코드·에셋을 직접 고치지 않는다.** 담당 세션이 명단에 없으면 **총괄이 그 역할 서브에이전트를 띄운다**(`Agent`, 이름 = 영문 역할명 `lead·balance·dev·ui·planner` — 한글 이름은 안 받는다, 프롬프트에 "SKILL.md와 `<역할>.md`를 읽고 따를 것 · 갈림길이면 멈추고 질문으로 돌려줄 것 · 보고는 최종 메시지로"). 명단에 `역할 = <이름> (총괄 서브에이전트)`로 적는다 — 사용자 결정 10/6.
  - **진짜 필요할 때만 띄운다.** 그 역할의 일이 실제로 생겼을 때만. 이미 떠 있으면 새로 띄우지 않고 `SendMessage`로 이어서 맡긴다.
  - **새 역할 종류**(이 폴더에 `<역할>.md` 추가)는 기존 넷에 안 맞는 일이 반복될 때만 만들고, 만들면 사용자에게 한 줄로 알린다.
- 역할 세션의 결과를 다시 검증하려고 같은 측정을 반복하지 않는다. 보고의 "검증" 항목이 사용자 문장을 재지 않았으면 그 세션에 되묻는다.

## 커밋 (사용자가 시킬 때만)
1. 명단의 각 세션에 `[질문] 커밋 예정 — 작업 중이라 아직 커밋하면 안 되는 파일 있나?`를 보낸다.
2. 답을 모아 커밋 단위를 사용자에게 보여 준다. 그다음 커밋한다.
