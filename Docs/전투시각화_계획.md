# 전투 시각화 계획 — "기능이 바뀌면 전투에서도 보여야 한다"

> UIUX + 아트 조사 · 계획 (10/20). 코드 · 씬 · 그림은 손대지 않았다.
> 사용자 요청: 「인게임에서 기능이 바뀌는 거는 전투에서도 실제로 비주얼적인 차이가 있어야 한다. (화살이 여러 개 · 관통탄 트레일 · 업그레이드가 이루어지면 비주얼 차이)」
> **문제 정의(한 줄)**: 플레이어는 전투 화면만 보고 "내가 산 것 · 고른 것이 지금 일하고 있나"를 알 수 없다 — 특히 화살 · 공격 방식이 바뀌는 효과와 합치기 보상 · 지역 특수 업그레이드.

- 🔴 **사용자 예시 「화살이 여러 개면 여러 개가 보이게」는 지금 *실제로 여러 발을 쏘지만 겹쳐서 한 발로 보인다*.** `Base.Shoot`은 모든 발을 같은 발사점(`_muzzle`) · 같은 착탄점 · 같은 꼭짓점으로 쏜다 — 사거리 안 적이 화살 수보다 적으면 궤적이 픽셀 단위로 겹친다(`_targets[i % _targets.Count]`). 궁병의 `Unit.Shoot`(화살 강화기 신화로 타워 화살 수를 받을 때)도 같다. 궁술수련관 신화의 3연발(`Unit.Burst`)만 시간차라 보인다.
- 🔴 **관통은 화살 모양이 전혀 안 바뀐다** — `Projectile.Pierce`는 플래그 · 배율만 세운다. 관통한 순간 표시도 없다(맞은 적마다 기존 파편 · 숫자만).

**P1 (행동이 바뀌는 것 — 사용자 예시 같은 것) 11개**

1. **관통탄 특허국** — 관통 화살에 흰 꼬리(F1) + 적을 뚫는 순간 흰 섬광(F3)
2. **관통탄 특허국 신화**(관통 타격마다 피해 ×2) — 뚫을 때마다 꼬리가 한 칸씩 길어지고 섬광이 노랑으로(F1 · F3)
3. **최신 엔진 부품** 「화살 수 +1」 — 여러 발이 부채꼴로 갈라져 날아간다(F2)
4. **화살 강화기 신화**(궁병이 타워 효과를 받음) — 궁병 화살도 F2 · 관통 꼬리를 그대로 받는다(같은 코드 길)
5. **처치하면 더 쏘는 화살** — 최신 엔진 부품 신화 · 오버드라이브 신화 · 「연사」 업그레이드 — 추가 발은 노란 꼬리(F1)
6. **사거리 증가** — 조준연산코그 · 신화 — 사거리 늘 때 그 타워 둘레로 고리(F4)
7. **광역 공격** — 툰드라 맘모스(아군 포함) · 교황청 강타 — 맞는 범위에 고리(F4, 아군도 맞으면 빨강)
8. **부활** — 죽지 않는 전사 · 노동의 기계화 신화(5초 뒤) — 일어나는 순간 기둥(F6), 기다리는 5초는 그 자리 점(F5)
9. **불태움** — 기름투하대 신화 — 타는 동안 몸 위 불꽃 점(F5 + 기존 `FlameBit`)
10. **감속** — 사냥꾼의 활(업그레이드) · 풍차 신화(적 이동속도 ×0.5) — 느린 동안 하늘색 점(F5)
11. **업그레이드가 전투에 들어간 것 표시** — 숫자 업그레이드는 전투 시작 알림(F9), 터지는 업그레이드는 발동 표식(F8) — **Q1 답에 따라 범위가 바뀐다**

## 1. 연출 부품 정의

공통 규칙 — 프로토타입이라 **작고 짧게**. 모두 **1/8칸(그림 1px) 격자**에 맞춘 네모로 그린다. 색은 이펙트에만(CLAUDE.md §5) — 색이 필요한 부품은 **버프 선 여섯 색(`BuffLinkFx.ColorOf(BuffKind)`)이나 이미 쓰는 이펙트 색**에서 고른다. 새 색 체계를 만들지 않는다.

### F1 투사체 꼬리
- 모양: 화살(5×3px) 꼬리 쪽으로 지난 자리 점 3~4개, 뒤로 갈수록 1px → 사라짐. 0.15초 안에 지워진다.
- 색: 관통 = 흰(화살과 같은 흰이라 "길어진 화살"로 읽힘) · 처치 추가 발 = 노랑(`SparkColor`). 관통 신화는 맞힐 때마다 점 +1.
- 구현 방식: `BuffLinkFx`와 같이 **화면의 꼬리 전부를 메시 하나로**. 화살마다 `TrailRenderer`/GameObject를 붙이지 않는다.
- 크기: 중간.

### F2 갈래 발사
- 모양: 한 번에 N발이면 발마다 꼭짓점 높이를 ±0.25칸씩 벌리거나(부채꼴), 0.04초씩 늦게 쏜다. 둘 중 하나.
- 🔴 **이건 그림만이 아니다** — 궤적이 바뀌면 착탄 자리 · 시각이 조금 달라져 맞는 적이 바뀔 수 있다. → §5 Q2.
- 크기: 작음.

### F3 색 섬광
- 모양: 기존 `FxDirector.HitSpark`(맞은 방향 부채꼴 파편)를 색만 바꿔 한 번 더 부른다. 새 파티클 없음.
- 색: 관통 = 흰 · 관통 신화 = 노랑 · 고지 보너스(기름투하대) = 주황(불꽃 색) · 반사 = 보라(디버프 색).
- 크기: 작음.

### F4 퍼지는 고리
- 모양: 1px 원(`Unit.CircleSprite(true)`와 같은 그림)이 0.3초 동안 반지름 0 → 효과 반지름으로 퍼지며 흐려진다.
- 쓰는 곳: 광역 공격의 실제 반지름 · 타워 사거리가 바뀐 순간의 새 사거리.
- 색: 광역 = 흰(아군도 맞는 맘모스는 빨강) · 사거리 = 버프 선 스탯 빨강.
- 동시 상한(예: 24개)과 같은 유닛 솎기 시간(0.5초)을 둔다.
- 크기: 중간.

### F5 몸 상태 점
- 모양: 상태가 붙어 있는 동안 머리 위 2×2px 점이 0.5초 주기로 깜빡인다. 상태가 둘이면 점 둘을 가로로.
- 색: 불탐 = 주황(`FlameBit` 색) · 감속 = 하늘(가속 색) · 디버프(공격력 감소 등) = 보라 · 부활 대기 = 초록(소환 색).
- 그리는 쪽은 `DamageNumbers`처럼 **관리자 하나 + 메시 하나** — 상태가 있는 유닛만 넣는다.
- 크기: 중간.

### F6 솟는 기둥
- 모양: 발밑에서 키만큼 1px 흰 세로 막대가 올라가고 꼭대기에 초록 점 하나, 0.3초.
- 쓰는 곳: 다시 일어나기 · 작은 타워 재건 · "그 자리에서" 소환(성 밖 소환이 왜 거기서 나왔는지).
- 크기: 작음.

### F7 층 배수 글자
- 모양: 발동한 층 옆(가속 배지와 같은 자리)에 「×2」가 0.4초 떴다 사라진다. 글꼴 · 테두리는 `TowerBadge`의 3×5 숫자 그대로.
- 쓰는 곳: 한 번 발동에 효과를 2번 내는 모든 것 — 늪지 · 물레방앗간 신화 · 군주제 · 라이칸스로프 신화 · 스팀바론 신화. 곱해지면 「×4」.
- 크기: 작음.

### F8 업그레이드 발동 표식 — Q1 · Q3
- 모양: 효과가 터진 유닛 머리 위에 그 업그레이드 아이콘이 0.5초(위로 1칸 뜨며 사라짐). 버프 글자(`BuffTexts`)와 같은 자리 규칙 · 흩뜨림.
- 🔴 **새 그림 필요** — 지금 업그레이드 아이콘은 `Assets/Sprites/Upgrades/*.png` 41장 모두 **32×32**(UI용). 전장에서 그대로 쓰면 4칸(유닛 4배)이라 너무 크고, 줄이면 도트가 뭉갠다 → **8×8 전장판**을 따로 그려야 한다. 그리기 싫으면 Q3의 대안(아이콘 없이 색 섬광만).
- 크기: 중간(그림 제외).

### F9 전투 시작 알림 — Q1
- 모양: 전투 시작 0.5초 뒤, **내 본진의 화살 발사점(`Base.Muzzle`)에서** 대상(내 유닛 무리 · 내 타워들 · 층)으로 버프 선을 긋고 버프 글자를 띄운다. 기물 효과와 같은 부품이고 출발점만 다르다.
- 숫자만 바뀌는 업그레이드(숫돌 · 갑옷 수선 · 군화 · 군악대 · 철벽 · 조련장 · 화살촉 · 화살 공방 · 성벽 보강 · 국가주의)는 이걸로 충분하다고 본다 — 전투 중 계속 보일 것이 없다.
- 맵 효과(숲 · 초원 · 정글)도 같은 자리에서 — 출발점은 이미 있는 `MapMarker`(얼음 덩이) 방식을 넓힌다.
- 크기: 작음(규칙만 바뀌면).

### 성능 — 한 줄
**부품마다 "관리자 하나 · 메시 하나 · 풀 고정 개수 · 동시 상한 · 같은 대상 솎기 시간"** — `DamageNumbers`/`BuffLinkFx`/`CorpseFx`가 이미 이렇게 한다. 화살 · 유닛마다 GameObject · `TrailRenderer` · `ParticleSystem`을 붙이지 않는다(유닛 수백 · 화살 수백). 8배속 측정 때 꼬리 정점 수를 같이 본다.

## 2. 기물 — 효과 표

**지금 보이는 것** 칸의 낱말: 선 = 버프 선(`BuffLinks`, 색 = 종류) · 글자 = 버프 글자(`BuffTexts`) · 링 = 무적 노란 링 · 오라 = 공격력 오른 순간 빨간 원판(`Unit.FlashAttackAura`) · 숫자 = 데미지/회복 숫자 · 층 튐 = 발동한 층의 아이콘 튐 + 창 번쩍임 · 배지 = 층의 가속 · 쿨다운 · 멈춤 · 남은 수 표시(`TowerBadge`). 출처는 전부 코드에서 확인했다(해당 클래스에 `BuffLinks.*`/`FxDirector` 호출이 있는지).
"확인 필요" = 코드로는 보일 것 같지만 캡처로 못 봤다.

## 6. 사용자에게 물을 것

**Q1. 업그레이드 · 지역 특수에도 전투에서 선을 그을까요?** (지금 규칙: 켠 기물이 없으면 긋지 않는다 — ARCHITECTURE 「버프 선」)
- (가) **본진에서 긋는다** — 업그레이드의 "출발점"을 내 본진 화살 발사점으로 정한다(F9). 숫자 업그레이드는 전투 시작 때 한 번, 터지는 업그레이드는 터질 때마다. 화면에 선이 늘어난다.
- (나) **선은 그대로 안 긋고, 터질 때만 유닛 위 아이콘(F8)** — 출처가 "업그레이드"라는 게 아이콘으로 읽힌다. 8×8 아이콘 41장이 필요하다.
- (다) **지금대로 둔다** — 유지되면 남는 불편: 합치기 보상 20개 중 18개가 전투에서 안 보인다(§3).

**Q2. 화살 여러 발을 "보이게" 하려면 궤적을 바꿔야 합니다 — 판정이 조금 달라져도 될까요?**
지금 N발은 같은 궤적이라 겹친다(§0). (가) 꼭짓점을 발마다 ±0.25칸 벌림 — 착탄 자리가 조금 갈림 · (나) 0.04초씩 시차 — 착탄 자리는 같고 시각만 늦음(움직이는 적에게 덜 맞을 수 있음) · (다) 궤적은 그대로, 발사점에서 화살 그림만 부채꼴로 잠깐 벌렸다 모음(판정 무관, 덜 보임).

**Q3. 「업그레이드가 이루어지면 비주얼 차이」의 "업그레이드"가 무엇인가요?**
- (가) 합치기 보상 업그레이드(이 문서 §3) · (나) **기물의 등급이 오르는 것**(합치기로 고급 → 희귀 …) — 이 경우 지금 전장 탑 층에는 **등급이 전혀 안 보인다**(`Tower`에 등급 색 · 테두리 없음 — 상점 UI 탑에만 있음). 층 창틀을 등급 테두리 색(`BuildingRarity`)으로 칠하는 안이 새로 생긴다 · (다) 둘 다.

**Q4. 숫자만 바뀌는 효과(공격력 +5% · 체력 +30% · 고도 보너스 등)는 "버프 글자가 한 번 뜨는 것"으로 충분한가요?**
이 계획은 "충분하다"로 가정했다 — 행동이 바뀌는 효과(화살 · 범위 · 상태 · 부활)만 계속 보이는 연출을 준다. 숫자 효과도 계속 보이게(예: 강화된 유닛 몸에 1px 테두리) 하려면 유닛 수백에 상시 표시가 붙어 화면이 지저분해진다.

**Q5. 관통 꼬리 색 — 흰(화살이 길어 보임, 아트 톤에 가장 가까움) / 하늘(버프 선 가속 색) / 노랑(피격 파편 색) 중?** 이 계획은 흰을 가정했다.
